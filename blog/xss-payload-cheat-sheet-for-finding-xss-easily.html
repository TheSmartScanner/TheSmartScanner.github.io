XSS Payload Cheat Sheet for Finding XSS Easily

By SmartScanner 15 June 2026

Use this XSS cheat sheet to find cross-site scripting vulnerabilities faster, even if you are not a security expert.

What is XSS?

Cross-site scripting (XSS) is a common web application vulnerability that lets an attacker inject malicious JavaScript into a page. When a browser executes that script, it can steal cookies, hijack sessions, modify page content, or act on behalf of the user.

There are three main XSS types:

  • Stored XSS: malicious input is saved on the server and served to visitors later.
  • Reflected XSS: the payload is reflected immediately in the response, often through a URL parameter or form input.
  • DOM-based XSS: the browser executes injected code from client-side JavaScript.

How to use this cheat sheet

These payloads are designed to trigger a JavaScript alert, usually with alert(1). In a vulnerable input, the browser executes the payload and shows the alert box.

Typical test vectors include:

  • URL query strings and fragments
  • HTML form fields and search boxes
  • HTTP headers such as Referer and User-Agent
  • file upload metadata and JSON request bodies

Testing workflow

  1. Identify an input vector.
  2. Inject a payload into the parameter.
  3. Submit the request or reload the page.
  4. Look for the browser alert or unexpected script execution.

Testing strategy and limitations

1. Brute-force payload testing

A payload list means trying one payload after another until one works.

The drawbacks are obvious:

  • Manual testing takes time.
  • Automation still needs many requests and can be slow on a large site.
  • Repeating many payloads increases the chance of WAF detection.
  • Real applications may require custom encoding, escaping, or context-specific payloads.
  • This cheat sheet is a starting point, not a complete WAF evasion guide.

⚠️ Warning: Use this guide only on applications you own or are authorized to test. Unauthorized scanning or exploitation is illegal and unethical.

Notes

  • Adapt each payload to the target HTML or JavaScript context.
  • Use browser developer tools or a proxy to inspect how the payload appears in the response.
  • Confirm real XSS by checking the injected code path, not just the alert dialog.
  • In practice, use any event handler valid in the target element, such as onclick, onfocus, oninput, onmouseover, or onmouseenter, instead of relying only on onload and onerror.
  • Always test only on targets you are authorized to scan.
